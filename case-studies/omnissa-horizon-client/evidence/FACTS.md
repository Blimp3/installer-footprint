Status: extracted and verified line by line. Not interpreted. A case study write-up may use only facts from this file.

Each line is one observation from the raw data of 25 June 2026, with the raw lines that show it. Six extraction passes, one per topic, pulled the facts from the raw data. A separate verifier per topic re-read every cited line. A completeness check compared the list with the study questions. A last pass merged duplicates and was verified the same way.

## How to read this file

- **IDs.** `SET` = setup, sources and timeline. `R1` = run 1 (install only). `BR` = state carried from run 1 into run 2. `P1`, `P2`, `P3` = run 2 phase 1 (install), phase 2 and phase 3 (observation). The analysis labels phase 2 "after granting Full Disk Access". No raw line records a Full Disk Access grant to a vendor component (P2-20), and System Settings opened the Full Disk Access pane only at 17:31:04 CEST, in phase 3 (P3-50).
- **[category]** names the artefact type. **uncertain** marks a fact the data cannot fully prove. Its note says why.
- **Sources** give the raw file by alias and the 1-based line numbers that `grep -n` prints. `aggregate` means a count over the file. Its note gives the command. `run1/capture.pcap#dump` means the output of `tcpdump -nn -A -r run1/capture.pcap 2>/dev/null`.
- **Excerpts** are the redacted files in this folder. They keep the raw line numbers, so a citation such as `run2/unified.log:43337` is line 43337 in `run2.unified-log.txt`. `[N unrelated lines removed]` marks lines that `tools/redact.py` dropped. Snapshot, report and diff excerpts keep only vendor, installer and section-header lines. The DNS excerpts are empty by design, because no captured DNS query names a vendor domain. So a fact that cites another line (an Apple system process, a DNS record, a directory row, or a count over unrelated lines) can be checked only against the raw data. Paths and bundle IDs of other software show as `<unrelated>`. `build.sh` rebuilds every excerpt from the raw data.
- **Placeholders.** `<user>` = username. `<host>` = hostname. `<lan-ip>` = private address. `<ip>` = a public address that is not a vendor endpoint. `<user-tmp>` = per-user temporary folder. `<removed>` = an ID removed by the redaction (UUID, UDID, serial-like token, MAC or email address). `<dir>/<local-pkg>` = folder and file name of the owner's local copy of the run 1 package (a name chosen for the analysis, not the vendor's). `pass:<withheld>` = a passphrase in a vendor script. `<browser-vendor>/<browser>` = two browser folder names. Other public IP addresses and all unrelated software on the host are left out.
- **Times** are local time on the test Mac, CEST (UTC+02:00).
